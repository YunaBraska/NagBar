# Support

## Getting Help

Use GitHub issues for:

- reproducible bugs;
- backend compatibility problems;
- parser failures with sanitized fixture data;
- build or test failures;
- documentation gaps.

For security issues, use `SECURITY.md` instead of public issues.
Blank issues are disabled so bug reports and feature requests include the
minimum diagnostic fields needed for triage.

## Useful Issue Details

Include:

- NagBar version or commit;
- macOS version;
- Xcode version if building locally;
- backend type;
- sanitized backend URL shape;
- expected behavior;
- actual behavior;
- logs or fixture data with private values removed.

## Scope

Maintainer support is best effort. NagBar can help surface monitoring status,
but it is not a replacement for validating the monitoring server itself.

Unsupported:

- private infrastructure debugging without sanitized reproduction data;
- credentials or token handling through public issues;
- production release claims for local ad-hoc builds.
